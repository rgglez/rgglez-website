## Introduction

Late on October 20, 2026, I came across
<a href="https://x.com/midudev/status/2112812718856044738" target="_blank">a
post by @midudev on X</a> that caught my attention (and, frankly, left me
looking like 😨). A set of critical PHP vulnerabilities had been discovered that
could give attackers easy access to a shell on compromised servers. Patches were
expected the next day, October 21. The vulnerabilities became known as
**PHP2Shell**.

<YouTubeEmbed id="CuvRrItIdKs" title="@midudev: ¡Han hackeado PHP!" />

These vulnerabilities are particularly worrying because many websites use PHP
and exploitation is relatively straightforward for an attacker with basic
knowledge. PHP is one of the most widely used web programming languages. Popular
applications, especially WordPress, Joomla, and Drupal, depend on it. Exposure
could therefore have a significant impact on web security.

The vulnerabilities have a severity score of 9.2 out of 10 on the CVSS v4.0
scale. Their identifiers are
<a href="https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w" target="_blank">CVE-2026-109618</a>
and
<a href="https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp" target="_blank">CVE-2026-109619</a>.

Researchers from Wiz, Calif, and OpenAI reportedly found the bugs using
artificial intelligence and began reporting them on August 11, 2026.
<a href="https://watchtowr.com/intelligence/php-remote-code-execution-php2shell/" target="_blank">Public
exploits</a> also appear to be available. Attackers could thus compromise web
servers without advanced knowledge.

The vulnerabilities affect every PHP version since 5.4, released on March
1, 2012. The PHP Foundation says a 2024 code audit had already identified these
problems, but internal processes and concerns about breaking compatibility
delayed a fix.

## How the vulnerabilities are exploited

The main risk is that an attacker can execute arbitrary code directly on an
affected web server. A connection to the web server running vulnerable PHP is
enough. The attacker could take control of the server, access sensitive data,
change files, install malware, or use the server to attack other systems. PHP
normally runs as the web server user, such as `www-data` or `nobody`. If the
server is misconfigured or has other vulnerabilities, the attacker could
escalate privileges and gain full `root` access. Even without that, code
execution as the web server user is a serious risk. For example, an attacker
could install a web shell to explore the file system, read and write files, and
run operating system commands through a browser. They could also install malware
to steal login credentials, payment card data, or personal information. A
compromised server could be used for DDoS attacks, cryptomining, lateral
movement within its network, or spam.

<Aside title="Security note">

Exploiting these vulnerabilities does not require advanced programming or
hacking skills. An attacker with basic knowledge could use automated tools
available online. System administrators and web developers should therefore act
immediately to protect their servers and applications.

Applications do not need to have their own security bugs to be vulnerable to
PHP2Shell. The flaws are in the PHP interpreter itself, so any application
running on a vulnerable PHP version could be at risk. This includes WordPress,
Joomla, Drupal, and custom applications developed in house.

</Aside>

## Fixes and mitigation

Updating PHP is the only effective way to mitigate these vulnerabilities. Many
affected PHP versions no longer receive official support but may still be in
use. Administrators and developers should upgrade to a PHP release containing
the security fixes. If affected web servers cannot be updated, take them offline
and update the applications before exposing them to the internet again.

| **PHP branch** | **Vulnerable versions** | **First safe version** |
| :------------- | :---------------------- | :--------------------- |
| 8.5            | Earlier than 8.5.12     | 8.5.12                 |
| 8.4            | Earlier than 8.4.27     | 8.4.27                 |
| 8.3            | Earlier than 8.3.36     | 8.3.36                 |
| 8.2            | Earlier than 8.2.35     | 8.2.35                 |

### Older versions and security backports

PHP 8.1 and earlier no longer receive updates from the PHP project. PHP 8.2
reaches end of life on December 31, 2026. For older branches, the PHP security
team has published security backports for PHP 7.4, 8.0, and 8.1 to help those
compiling PHP from source or waiting for a vendor update.

Independent maintainer
<a href="https://github.com/sponsors/oerdnj" target="_blank">Ondřej Surý</a> has
<a href="https://codeberg.org/oerdnj/deb.sury.org/issues/145" target="_blank">published</a>
PHP 7.4, 8.0, and 8.1 releases with the security patches applied. Linux
distributions are expected to update their packages soon. Ubuntu, for example,
has already published security updates for PHP 7.4, 8.0, and 8.1 in its official
<a href="https://ubuntu.com/blog/php2shell-vulnerability-fixes-available" target="_blank">Ubuntu
Expanded Security Maintenance</a> repositories.

### Temporary mitigation

Many sites suggest temporary measures, such as disabling PHP functions or
lowering configuration values. These measures are not fully effective and cannot
guarantee server security. To protect a server fully, update PHP to a safe
version and restart the process or server so that the updated version is
actually running.

## Was my server compromised? Did it leave any traces?

The following script cannot tell you whether someone got into a server. It is
read only and searches for errors these flaws can leave during request startup,
as well as worker crashes, sessions, and child processes. It reads Apache,
nginx, and PHP-FPM logs, including rotated `.gz` files, and the journal for
those services.

A fatal error ending in `in Unknown on line 0` with memory exhaustion is a clue
for CVE-2026-109618. A patched PHP release writes the same line when a request
exhausts `memory_limit`, so it does not prove exploitation. CVE-2026-109619 may
occur without exhausting memory. It can appear as a timeout or worker crash,
also before a script starts.

The access log does not contain request bodies. If PHP runs in a container, run
the script inside it. A clean result, or logs that have already rotated away,
cannot settle the question.

Save the script and run it as root. It requires Bash 4 or later and `gzip` to
read compressed rotated logs.

**Read the script and the security note below it before running it.**

```bash
#!/bin/bash
# Read-only triage for PHP2Shell.
# CVE-2026-109618 / CVE-2026-109619.
#
# Does not prove a compromise. No findings do not rule one out.
# Patched PHP also writes the same fatal memory error.
# Request bodies are not in the access log.
#
# Usage: sudo bash php2shell-triage.sh

set -u

if ((BASH_VERSINFO[0] < 4)); then
  echo "Bash 4 or later is required." >&2
  exit 1
fi

if [[ ${EUID:-$(id -u)} -ne 0 ]]; then
  echo "Run as root to read the logs: sudo bash $0" >&2
  exit 1
fi

RED=$'\033[31m'
YEL=$'\033[33m'
GRN=$'\033[32m'
NC=$'\033[0m'

SINCE=2026-10-20

# Fatal error before PHP starts running a script.
PRESCRIPT_RE='in Unknown on line 0'
# The second form appears when memory_limit=-1.
OOM_RE='Allowed memory size of [0-9]+ bytes exhausted|Out of memory \(allocated'
TIMEOUT_RE='Maximum execution time of [0-9]+ seconds exceeded'
# Apache writes "exit signal Segmentation fault (11)", not "exit signal 11".
CRASH_RE='exited on signal (4|6|7|8|11)|SIGSEGV|SIGBUS|SIGABRT|segfault at|Segmentation fault|zend_mm_heap corrupted'
UPSTREAM_RE='upstream prematurely closed connection'
# User-Agents published by ELLIO on October 21, 2026.
UA_RE='php2shell-scan/109618|php2shell-109618|php2shell-verify/'

WEB_COMM_RE='^(php-fpm[0-9.]*|php-cgi[0-9.]*|apache2|httpd|nginx|lsphp[0-9]*|frankenphp)$'
TOOL_RE='^(sh|bash|dash|zsh|curl|wget|nc|ncat|netcat|python[0-9.]*|perl|ruby|socat|base64)$'

declare -a ERR_LOGS=()
declare -a ACC_LOGS=()
declare -A SEEN_LOG=()
declare -A WEB_USER=()
GZ_WARNED=0

section() { printf '\n[+] %s\n' "$1"; }
note() { printf '  %s\n' "$1"; }
ok() { printf '%b  %s%b\n' "$GRN" "$1" "$NC"; }
lead() { printf '%b  %s%b\n' "$YEL" "$1" "$NC"; }
bad() { printf '%b  %s%b\n' "$RED" "$1" "$NC"; }

remember() {
  local kind=$1 f=$2
  [[ -f $f && -r $f ]] || return 0
  [[ -n ${SEEN_LOG[$f]:-} ]] && return 0
  SEEN_LOG[$f]=1
  if [[ $kind == err ]]; then
    ERR_LOGS+=("$f")
  else
    ACC_LOGS+=("$f")
  fi
}

remember_glob() {
  local kind=$1 pat=$2 f
  shopt -s nullglob
  for f in $pat; do
    remember "$kind" "$f"
  done
  shopt -u nullglob
}

collect_logs() {
  remember_glob err '/var/log/apache2/error.log*'
  remember_glob err '/var/log/httpd/error_log*'
  remember_glob err '/var/log/nginx/error.log*'
  remember_glob err '/var/log/php*-fpm.log*'
  remember_glob err '/var/log/php*-fpm/*.log*'
  remember_glob err '/var/log/php-fpm/*.log*'
  remember_glob err '/var/log/syslog*'
  remember_glob err '/var/log/messages*'
  remember_glob err '/var/log/kern.log*'
  remember_glob acc '/var/log/apache2/access.log*'
  remember_glob acc '/var/log/apache2/other_vhosts_access.log*'
  remember_glob acc '/var/log/httpd/access_log*'
  remember_glob acc '/var/log/nginx/access.log*'

  local raw path ini
  while IFS= read -r raw; do
    raw=${raw%%#*}
    set -- $raw
    [[ $# -ge 2 ]] || continue
    path=$2
    path=${path%;}
    path=${path//\"/}
    path=${path//\$\{APACHE_LOG_DIR\}/\/var\/log\/apache2}
    [[ $path == /* ]] || continue
    [[ $path == *\$* ]] && continue
    case $path in
      off|stderr|syslog) continue ;;
    esac
    case $1 in
      ErrorLog|error_log) remember_glob err "${path}*" ;;
      CustomLog|access_log) remember_glob acc "${path}*" ;;
    esac
  done < <(grep -rhsE '^[[:space:]]*(ErrorLog|error_log|CustomLog|access_log)[[:space:]]+' \
    /etc/apache2 /etc/httpd /etc/nginx 2>/dev/null || true)

  while IFS= read -r ini; do
    ini=${ini%%#*}
    ini=${ini#*=}
    ini=${ini//[[:space:]\"\;]/}
    [[ $ini == /* ]] || continue
    remember_glob err "${ini}*"
  done < <(grep -rhsE '^[[:space:]]*error_log[[:space:]]*=' \
    /etc/php /etc/php.ini /etc/php.d /etc/php-fpm.conf /etc/php-fpm.d 2>/dev/null || true)
}

is_syslog() {
  case $1 in
    */syslog*|*/messages*|*/kern.log*) return 0 ;;
    *) return 1 ;;
  esac
}

match_file() {
  local re=$1 file=$2
  if [[ $file == *.gz || $file == *.gzip ]]; then
    if ! command -v gzip >/dev/null 2>&1; then
      if ((GZ_WARNED == 0)); then
        printf '  %s\n' "gzip is not installed. .gz logs will not be read." >&2
        GZ_WARNED=1
      fi
      return 0
    fi
    gzip -dc -- "$file" 2>/dev/null | grep -E -- "$re" || true
  else
    grep -E -- "$re" "$file" 2>/dev/null || true
  fi
}

show_tail() {
  printf '%s\n' "$1" | tail -5 | sed 's/^/    /'
}

count_lines() {
  printf '%s\n' "$1" | grep -c .
}

load_web_users() {
  local u
  for u in www-data apache nginx http nobody www; do
    WEB_USER[$u]=1
  done
  while IFS= read -r u; do
    [[ $u =~ ^[A-Za-z0-9._-]+$ ]] || continue
    WEB_USER[$u]=1
  done < <(grep -rhsE '^[[:space:]]*(User|user)[[:space:]]+' \
    /etc/apache2 /etc/httpd /etc/nginx \
    /etc/php/*/fpm/pool.d /etc/php-fpm.d 2>/dev/null \
    | awk '{gsub(/[;=]/, " ", $0); print $2}' || true)
}

journal_units() {
  command -v systemctl >/dev/null 2>&1 || return 0
  systemctl list-units --type=service --all --no-legend --plain 2>/dev/null \
    | awk '{print $1}' \
    | grep -E '^(php.*fpm|apache2|httpd|nginx)\.service$' || true
}

echo "=== PHP2Shell triage (read only) — $(date) ==="
echo "Does not prove a compromise. A clean result does not rule one out."

collect_logs
load_web_users

J_ARGS=()
if command -v journalctl >/dev/null 2>&1; then
  while IFS= read -r unit; do
    [[ -n $unit ]] && J_ARGS+=(-u "$unit")
  done < <(journal_units)
fi

section "Logs to be read"
if ((${#ERR_LOGS[@]})); then
  printf '  error: %s\n' "${ERR_LOGS[@]}"
else
  note "No readable error logs. Log searches will find nothing."
fi
if ((${#ACC_LOGS[@]})); then
  printf '  access: %s\n' "${ACC_LOGS[@]}"
else
  note "No readable access logs."
fi

section "PHP binaries"
note "The version number is not enough. A distribution may patch without changing it."
note "The php in PATH may not be the SAPI serving the website."
declare -A SEEN_BIN=()
bins=()
shopt -s nullglob
if command -v php >/dev/null 2>&1; then
  bins+=("$(command -v php)")
fi
for b in /usr/sbin/php-fpm* /usr/sbin/php-cgi* /usr/bin/php[0-9]*; do
  [[ -x $b ]] || continue
  bins+=("$b")
done
shopt -u nullglob
shown=0
for b in "${bins[@]+"${bins[@]}"}"; do
  [[ -n ${SEEN_BIN[$b]:-} ]] && continue
  SEEN_BIN[$b]=1
  shown=1
  ver=$("$b" -v 2>/dev/null | head -1 || true)
  printf '  %s — %s\n' "$b" "${ver:-no version}"
done
if ((shown == 0)); then
  note "No php in PATH or /usr/sbin."
elif command -v php >/dev/null 2>&1; then
  note "CLI values, not necessarily those of FPM or mod_php:"
  php -r 'printf("  memory_limit=%s  upload_progress=%s  error_log=%s\n", ini_get("memory_limit"), ini_get("session.upload_progress.enabled"), ini_get("error_log"));' \
    || true
fi

section "Fatal errors before a script starts"
note "The string is: in Unknown on line 0."
note "With memory exhaustion, it is a clue for CVE-2026-109618."
note "Patched PHP writes the same line if it exhausts memory_limit."
note "Check the date. Look from October 20, 2026 onward."

if ((${#ERR_LOGS[@]} == 0 && ${#J_ARGS[@]} == 0)); then
  note "No error logs or journal for these units. This search was skipped."
else

oom_n=0
timeout_n=0
other_n=0
oom_s=""
timeout_s=""
other_s=""

classify_prescript() {
  local src=$1 hits=$2 line
  [[ -n $hits ]] || return 0
  while IFS= read -r line; do
    [[ -n $line ]] || continue
    if printf '%s\n' "$line" | grep -qE -- "$OOM_RE"; then
      oom_n=$((oom_n + 1))
      if ((oom_n <= 5)); then
        oom_s+="    $src: $line"$'\n'
      fi
    elif printf '%s\n' "$line" | grep -qE -- "$TIMEOUT_RE"; then
      timeout_n=$((timeout_n + 1))
      if ((timeout_n <= 5)); then
        timeout_s+="    $src: $line"$'\n'
      fi
    else
      other_n=$((other_n + 1))
      if ((other_n <= 5)); then
        other_s+="    $src: $line"$'\n'
      fi
    fi
  done <<< "$hits"
}

for f in "${ERR_LOGS[@]+"${ERR_LOGS[@]}"}"; do
  classify_prescript "$f" "$(match_file "$PRESCRIPT_RE" "$f")"
done

if ((${#J_ARGS[@]})); then
  jhits=$(journalctl --since "$SINCE" -q --no-pager "${J_ARGS[@]}" 2>/dev/null \
    | grep -E -- "$PRESCRIPT_RE" || true)
  classify_prescript "journal" "$jhits"
elif command -v journalctl >/dev/null 2>&1; then
  note "systemd has no php-fpm, apache, or nginx units."
else
  note "journalctl is not installed."
fi

if ((oom_n)); then
  lead "Memory exhaustion before a script: $oom_n"
  printf '%s' "$oom_s"
else
  ok "No pre-script memory exhaustion in the data read."
fi
if ((timeout_n)); then
  lead "Timeout before a script: $timeout_n. Weak clue for CVE-2026-109619."
  printf '%s' "$timeout_s"
else
  ok "No pre-script timeout in the data read."
fi
if ((other_n)); then
  lead "Other fatal errors before a script: $other_n"
  printf '%s' "$other_s"
else
  ok "No other pre-script fatal errors in the data read."
fi

fi

section "Worker crashes"
note "Apache error logs need not mention apache or php in the line."
note "In syslog and the kernel log it must, as other programs crash there too."

if ((${#ERR_LOGS[@]} == 0 && ${#J_ARGS[@]} == 0)); then
  note "No error logs or journal for these units. This search was skipped."
else

crash_any=0
for f in "${ERR_LOGS[@]+"${ERR_LOGS[@]}"}"; do
  hits=$(match_file "$CRASH_RE" "$f")
  [[ -n $hits ]] || continue
  if is_syslog "$f"; then
    hits=$(printf '%s\n' "$hits" | grep -Ei 'php|apache|httpd|nginx|www-data|fpm' || true)
  fi
  [[ -n $hits ]] || continue
  crash_any=1
  lead "$f ($(count_lines "$hits"))"
  show_tail "$hits"
done

if command -v journalctl >/dev/null 2>&1; then
  khits=$(journalctl -k --since "$SINCE" -q --no-pager 2>/dev/null \
    | grep -E 'segfault at|general protection' \
    | grep -Ei 'php|apache|httpd|nginx' || true)
  if [[ -n $khits ]]; then
    crash_any=1
    lead "kernel ($(count_lines "$khits"))"
    show_tail "$khits"
  fi
  if ((${#J_ARGS[@]})); then
    jhits=$(journalctl --since "$SINCE" -q --no-pager "${J_ARGS[@]}" 2>/dev/null \
      | grep -E -- "$CRASH_RE" || true)
    if [[ -n $jhits ]]; then
      crash_any=1
      lead "journal ($(count_lines "$jhits"))"
      show_tail "$jhits"
    fi
  fi
fi
if ((crash_any == 0)); then
  ok "No worker crashes in the data read."
fi

fi

section "nginx and the PHP worker"
note "upstream prematurely closed connection can also result from a normal timeout."
if ((${#ERR_LOGS[@]} == 0)); then
  note "No error logs. This search was skipped."
else
up_any=0
for f in "${ERR_LOGS[@]+"${ERR_LOGS[@]}"}"; do
  hits=$(match_file "$UPSTREAM_RE" "$f")
  [[ -n $hits ]] || continue
  if is_syslog "$f"; then
    hits=$(printf '%s\n' "$hits" | grep -Ei 'nginx' || true)
  fi
  [[ -n $hits ]] || continue
  up_any=1
  lead "$f ($(count_lines "$hits"))"
  show_tail "$hits"
done
if ((up_any == 0)); then
  ok "That string was not found in the data read."
fi
fi

section "Published scanner User-Agents"
note "A match is a recorded attempt, not proof of code execution."
note "The common format does not store User-Agent; combined does."
if ((${#ACC_LOGS[@]} == 0)); then
  note "No access logs. This search was skipped."
else
ua_any=0
for f in "${ACC_LOGS[@]+"${ACC_LOGS[@]}"}"; do
  hits=$(match_file "$UA_RE" "$f")
  [[ -n $hits ]] || continue
  ua_any=1
  lead "$f ($(count_lines "$hits"))"
  show_tail "$hits"
done
if ((ua_any == 0)); then
  ok "No such User-Agents in the access logs read."
fi
fi

section "Sessions on disk"
note "PHP deletes them after about 24 idle minutes. Empty proves nothing."
note "Redis and Memcached are not checked."
declare -A SESS_DIR=()
add_sess() {
  local p=$1
  [[ $p =~ ^[0-9]+\;(.*)$ ]] && p=${BASH_REMATCH[1]}
  p=${p//\"/}
  [[ $p == /* && -d $p ]] || return 0
  SESS_DIR[$p]=1
}
add_sess /var/lib/php/sessions
add_sess /var/lib/php/session
add_sess /tmp
if command -v php >/dev/null 2>&1; then
  add_sess "$(php -r 'echo ini_get("session.save_path");' 2>/dev/null || true)"
fi
while IFS= read -r p; do
  p=${p#*=}
  p=${p//[[:space:]\"]/}
  p=${p%%;}
  add_sess "$p"
done < <(grep -rhsE 'session\.save_path[[:space:]]*=' \
  /etc/php /etc/php.ini /etc/php-fpm.d /etc/php-fpm.conf 2>/dev/null || true)

sess_any=0
for d in "${!SESS_DIR[@]}"; do
  depth=3
  [[ $d == /tmp ]] && depth=1
  up=$(find "$d" -maxdepth "$depth" -type f -name 'sess_*' -size -2M -print0 2>/dev/null \
    | xargs -0 -r grep -l 'upload_progress_' 2>/dev/null || true)
  code=$(find "$d" -maxdepth "$depth" -type f -name 'sess_*' -size -2M -print0 2>/dev/null \
    | xargs -0 -r grep -lE '<\?php|<\?=' 2>/dev/null || true)
  if [[ -n $up ]]; then
    sess_any=1
    lead "upload_progress_ in $d. Could be CVE-2026-109619 or a legitimate progress bar."
    printf '%s\n' "$up" | head -10 | sed 's/^/    /'
  fi
  if [[ -n $code ]]; then
    sess_any=1
    bad "PHP code inside a session in $d."
    printf '%s\n' "$code" | head -10 | sed 's/^/    /'
  fi
done
if ((sess_any == 0)); then
  ok "None of these findings in sessions still on disk."
fi

section "Child processes and binaries in /tmp"
note "PHP mail() launches /bin/sh. sendmail is not flagged."
note "An image converter can also be a worker child process."
declare -A WORKER=()
if ps -eo pid=,comm= >/dev/null 2>&1; then
  while read -r pid comm; do
    [[ $comm =~ $WEB_COMM_RE ]] && WORKER[$pid]=1
  done < <(ps -eo pid=,comm=)
  proc_any=0
  while read -r user pid ppid comm args; do
    [[ -n ${WORKER[$ppid]:-} ]] || continue
    [[ $comm =~ $TOOL_RE ]] || continue
    case $args in
      *sendmail*|*postfix*|*exim*|*msmtp*) continue ;;
    esac
    proc_any=1
    bad "$user pid=$pid ppid=$ppid $args"
  done < <(ps -eo user=,pid=,ppid=,comm=,args=)
  while read -r user pid; do
    [[ -n ${WEB_USER[$user]:-} ]] || continue
    exe=$(readlink "/proc/$pid/exe" 2>/dev/null || true)
    case $exe in
      /tmp/*|/var/tmp/*|/dev/shm/*|memfd:*) ;;
      *) continue ;;
    esac
    proc_any=1
    bad "$user pid=$pid exe=$exe"
  done < <(ps -eo user=,pid=)
  if ((proc_any == 0)); then
    ok "No such child processes or web-user binaries in /tmp."
  fi
else
  note "ps does not support -eo. Install procps."
fi

section "auto_prepend_file and unusual handlers"
note "Not an attack error. This is common persistence after RCE."
note "Some legitimate hosting services use auto_prepend_file."
declare -A SEEN_ROOT=()
roots=()
shopt -s nullglob
for r in /var/www /srv/www /srv/http /usr/share/nginx/html /home/*/public_html /home/*/www; do
  [[ -d $r ]] && roots+=("$r")
done
shopt -u nullglob
while IFS= read -r r; do
  r=${r//[\"\;]/}
  [[ -d $r ]] && roots+=("$r")
done < <(grep -rhsE '^[[:space:]]*(DocumentRoot|root)[[:space:]]+' \
  /etc/apache2 /etc/httpd /etc/nginx 2>/dev/null \
  | awk '{print $2}' || true)

prep_any=0
PREPEND_RE='auto_prepend_file|auto_append_file|(AddHandler|AddType|SetHandler).*php.*\.(jpe?g|png|gif|ico|txt|css|js|svg|webp|html)'
for r in "${roots[@]+"${roots[@]}"}"; do
  [[ -n ${SEEN_ROOT[$r]:-} ]] && continue
  SEEN_ROOT[$r]=1
  hits=$(find "$r" -xdev -maxdepth 6 \( -name '.htaccess' -o -name '.user.ini' \) -type f -print0 2>/dev/null \
    | xargs -0 -r grep -nE "$PREPEND_RE" 2>/dev/null | head -20 || true)
  [[ -n $hits ]] || continue
  prep_any=1
  lead "$r"
  printf '%s\n' "$hits" | sed 's/^/    /'
done
if ((prep_any == 0)); then
  ok "None of these findings in common document roots."
fi

echo
echo "=== End. Yellow and red indicate clues, not a verdict. ==="
echo "Error logs read: ${#ERR_LOGS[@]}. Access logs read: ${#ACC_LOGS[@]}."
if ((${#ERR_LOGS[@]} == 0)); then
  echo "No error logs were read. This result says nothing."
fi
```

<Aside title="Security note about the script" type="warning">

This is triage, not an investigation. A green result does not rule out a
compromise. PHP sessions are deleted after about 24 minutes, the access log does
not include request bodies, and an attacker who reached root may have cleared
the logs.

If you see a fatal error before a script starts, a worker crash, or an
unfamiliar child process, take the server out of service and preserve the logs.
Update PHP and reinstall from a clean copy. Deleting the suspicious file alone
is insufficient.
